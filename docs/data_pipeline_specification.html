수집 대상 방식 원천 (Source) 주요 수집 항목 수집 주기 Cache TTL

02

수집 파이프라인 단계별 처리 프로세스

외부 데이터를 수집하여 스코어링 엔진(core/)에 전달하기까지의 4단계 데이터 파이프라인 흐름.

STEP 01
Trigger & Request
종목 조회 시 st.cache_data 검증 후 외부 수집 세션 생성.
STEP 02
Fetch & Rate Limit
Random User-Agent 및 딜레이(0.3s) 적용 후 HTML/JSON 수집.
STEP 03
Parsing & Cleaning
BeautifulSoup 파싱, 불필요한 특수문자/광고 및 불용어 정제.
STEP 04
Validation & Store
Null/이상치 체크 후 데이터프레임 표준화 및 Cache 등록.
03

웹 스크래핑 세부 규칙 및 세션 관리

비공식 수집 경로의 안정성을 유지하기 위한 모듈별 세부 처리 규칙.

종목 토론방 크롤러 naver_scraper.py
  • 페이지 동적 탐색: 게시글 밀도에 따라 상위 1~3페이지 파싱.
  • 헤더 위장: Chrome/Firefox 최신 User-Agent 로테이션.
  • 텍스트 정제: [광고], [스팸] 패턴 및 중복글 필터링.
외국인·기관 수급 크롤러 fundamentals.py
  • 수급 데이터 수집: 최근 20거래일 외국인/기관 순매수 수량 및 금액.
  • 예외 데이터 처리: 거래정지/신규상장 종목의 NaN 데이터 안전 처리.
  • 지수 비교: KOSPI/KOSDAQ 동기간 수급과 대조하여 상대 강도 산출.
04

장애 대응(Fail-safe) 및 영속화 정책

네트워크 차단, API 장애, HTML DOM 구조 변경 등 예외 발생 시 서비스 지속성 확보.

Graceful Degradation
스크래핑 실패 시 중립 점수(Neutral Score: 50점)를 반환하여 가용성 보장.
Multi-Tier Fallback
FDR 실패 시 yfinance 자동 전환, 종목 목록 실패 시 로컬 20종목 폴백.
Score History Persistence
계산된 점수 이력은 data/score_history.json 파일에 영속화.
