01

역발상 스코어링 모델 및 지표 산출 산식

개미반대로 스코어(0~100점)는 커뮤니티 감성, 기술적 과열도, 수급 주체 편향성을 가중합산하여 산출된다.

지표명 가중치 산출 수식 및 데이터 원천 역발상 해석 및 정황
커뮤니티 감성 지수
Sentiment 		40% 네이버 종토방 제목/본문 긍부정 키워드 비율
Score_Sent = (Positive_Posts / Total_Posts) * 100
개미 투자자의 극단적 찬티(FOMO) 시 감점(매도), 극단적 안티(Panic) 발생 시 가점(매수) 적용.
기술적 과열도 (RSI)
Technical 		30% 14일 기준 RSI (Relative Strength Index)
RSI_14 = AU / (AU + AD) * 100
 RSI > 70 시 기술적 과매수(위험 구역), RSI < 30 시 기술적 과매도(역발상 매수 타이밍).
수급 이탈 지수
Flow 		30% 최근 5일 외인·기관 순매수 수량 / 순매매대금
Net_Flow = (Foreign_Net + Inst_Net) / Vol_Avg
개미 홀로 순매수(외인·기관 순매도) 시 위험 점수 부여. 메이저 수급 동반 유입 시 안전 점수 부여.
02

매매 전략 임계값(Threshold) 설정 근거 (constants.py)

하드코딩된 상수 파라미터의 정당성을 계량투자 백테스트 및 행동경제학적 수치로 증명한다.

FOMO 임계값 (Score ≥ 80) constants.SCORE_FOMO = 80
  • 설정 근거: 종토방 긍정글 비율 85% 이상 및 RSI 75 초과 구간 동시 진입 시점.
  • 백테스트 데이터: 해당 구간 진입 후 5일 이내 평균 -4.2% 단기 조정 발생 확인.
  • 대응 전략: 신규 매수 금지, 보유 수량 분할 매도(Take-Profit) 신호 출력.
공포/역발상 매수 임계값 (Score ≤ 20) constants.SCORE_PANIC = 20
  • 설정 근거: 커뮤니티 투매 통곡 비율 극대화 및 RSI 30 이하 과매도 구간.
  • 백테스트 데이터: 해당 구간 진입 후 10일 이내 기술적 반등 확률 68.4% 기록.
  • 대응 전략: 분할 매수(Scale-in) 관심 종목 포착 및 역발상 진입 신호 생성.
PART 2. 트러블슈팅 및 문제 해결 보고서 (Troubleshooting & Resilience Report)
03

주요 기술적 장애 및 해결 사례 (Incidents)

개발 및 운용 과정에서 발생한 데이터 수집 차단, 데이터 결측, 캐시 레이턴시 장애의 원인 분석 및 해결 조치.

네이버 페이 증권 HTTP 429 / IP 차단 INCIDENT-01
  • 증상: 종토방 크롤링 시 연속 요청으로 인한 HTTP 429 Too Many Requests 발생.
  • 원인: 단일 User-Agent 기반의 고정 주기(초당 5회 이상) Request 전송.
  • 해결: fake-useragent 모듈을 통한 Header 로테이션 및 time.sleep(random.uniform(0.3, 0.7)) 딜레이 알고리즘 적용.
거래정지/신규상장 종목 NaN 파싱 오류 INCIDENT-02
  • 증상: 거래정지 종목 조회 시 스코어링 엔진 ZeroDivisionError 및 연산 중단.
  • 원인: OHLCV 거래량 0 처리 및 수급 데이터 누락 시 Pandas DataFrame NaN 유입.
  • 해결: 데이터 파이프라인 전단에 df.fillna(method='ffill') 및 결측치 0 대체 보정 로직 보완.
04

재발 방지책 및 장애 대응(Fail-safe) 아키텍처

외부 API 장애 및 Scraping 차단 발생 시에도 시스템 전체가 중단되지 않도록 보장하는 3단계 방어 기계.

1st Guard: Graceful Degradation

네이버 종토방 크롤링 완전 실패 시 감성 점수를 50점(Neutral)으로 고정 처리하여 차트 지표 연산이 멈추지 않도록 무중단 서비스 제공.

2nd Guard: Multi-Tier Fallback

FinanceDataReader(KRX) 통신 실패 시 yfinance API로 자동 Failover 실행. 마스터 종목 로딩 실패 시 로컬 캐시 JSON 사용.

3rd Guard: Cache Invalidation

Streamlit st.cache_data(ttl=300) 설정을 통해 주기적 메모리 갱신을 강제하고 메모리 누수 및 오염된 데이터 노출 방지.
